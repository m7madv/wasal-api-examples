# وصل — أمثلة API لقراءة معلومات حوالات شام كاش

أمثلة تعليمية للمطورين السوريين الذين يبنون متاجر وأنظمة اشتراكات ويريدون عرض معلومات الحوالات داخل مشروعاتهم.

**وصل خدمة مستقلة غير رسمية وليست تابعة لشام كاش.** واجهة وصل لا ترسل الأموال. هذا لا يعني أن جلسة مزود شام كاش مقيدة تقنيًا بالقراءة فقط. لا يوجد ضمان لمزامنة فورية؛ تعتمد القراءة على المصدر والجلسة والاتصال.

- [الدليل والنموذج ببيانات وهمية](https://wasalnow.com/sham-cash-api?utm_source=github&utm_medium=developer_resource&utm_campaign=dev_integration_20260920&utm_content=api_examples)
- [الموقع والاشتراك](https://wasalnow.com/?page=subscription)
- [طلب API الرسمي من شام كاش](https://shamcash.sy/ar/apiRequest) — مسار منفصل لمن يحتاج تكاملًا رسميًا.

## جرّب المثال دون حساب أو محفظة

يتطلب المثال Node.js 18 أو أحدث، ولا يحتاج إلى حزم خارجية:

```sh
node read-payments.mjs
```

الوضع الافتراضي يستخدم بيانات وهمية داخل الملف، **ولا ينفذ أي طلب شبكة**. يعرض ملخصًا لعدد حركات الإيداع والخصم وحالة المزامنة. لا يؤكد اشتراكات أو يرسل إشعارات أو يحول أموالًا.

## القراءة الفعلية بعد إعداد الحساب

الترتيب: إنشاء حساب ← اشتراك فعال ← ربط حسابك والتحقق من القراءة ← إنشاء مفتاح API.

ضع المفتاح في متغير البيئة `WASAL_API_KEY` على خادمك، ثم شغّل:

```sh
node read-payments.mjs --live
```

ينفذ المثال طلبًا واحدًا إلى `GET https://wasalnow.com/api/v1/payments?limit=25`، بمهلة 15 ثانية ودون اتباع إعادة التوجيه. إذا كانت المزامنة قديمة أو القراءة غير موثوقة، يعرض الحالة وينهي التنفيذ برمز `2`. لا يحوّل فشل القراءة إلى عبارة «لا توجد حوالات».

يعرض المثال ملخصًا فقط ولا يطبع المفتاح أو بيانات الأطراف أو ملاحظاتهم. يعرض الصفحة الأولى فقط؛ وليس عامل مزامنة يعمل باستمرار.

طلب مكافئ من خادم مشروعك:

```sh
curl 'https://wasalnow.com/api/v1/payments?limit=25' \
  -H 'Authorization: Bearer YOUR_READ_KEY'
```

لا تضع المفتاح في رابط عام، أو شفرة المتصفح، أو مستودع، أو لقطة شاشة. لا تستخدم مفتاحًا حقيقيًا عند مشاركة المثال.

## ملف Postman

استورد [wasal.postman_collection.json](./wasal.postman_collection.json). يحتوي على طلبين: قراءة حالة الحساب، وقراءة صفحة الحوالات. قيمة `api_key` فارغة في الملف؛ ضع القيمة في خزنة Postman أو بيئة محلية خاصة بك، ولا تشارك أو تصدّر ملفًا يحتوي عليها. اجعل متغيرًا محليًا باسم `api_key` يتغلب على القيمة الفارغة في المجموعة.

## كيف تفهم الاستجابة؟

| الحقل | المعنى |
| --- | --- |
| `data` | الحوالات التي أعادتها هذه الصفحة |
| `direction` | `incoming` للإيداع، و`outgoing` للخصم |
| `amount_minor` و`exponent` | المبلغ كسلسلة بوحدات العملة الصغرى ومكان الفاصلة؛ تجنب التقريب العشري غير المقصود |
| `currency` | العملة؛ لا تطابق الدولار والليرة باعتبارهما متساويين |
| `provider_id` و`account_id` | مرجع المصدر والحساب عند توفرهما؛ تحقّق من قيمهما قبل منع التكرار |
| `note` | ملاحظة المصدر؛ قد تكون `null` أو نصًا فارغًا |
| `received_at` و`observed_at` | وقت الحوالة من المصدر ووقت حفظها في وصل؛ ليسا بالضرورة متساويين |
| `next_cursor` | إذا لم يكن فارغًا فهناك صفحة أخرى؛ استخدمه بقيمة معامل `cursor` |
| `sync.stale` و`sync.error` | حالة حداثة القراءة والخطأ؛ افحصهما قبل الاعتماد على النتائج |

راجع [المواصفات الحالية](https://wasalnow.com/openapi.json) قبل بناء تكامل إنتاجي. المواصفات والسلوك المنشور هما المرجع عند تغير الواجهة.

## قبل تأكيد طلب داخل متجرك

1. لا تعتمد على المبلغ وحده؛ قد يصل المبلغ نفسه من عميلين.
2. تحقّق من اتجاه الحركة والعملة وحالة التأكيد والمرجع المطلوب. أرسل الحالات الملتبسة للمراجعة.
3. امنع معالجة الحوالة مرتين بقيد فريد على الحساب ومعرّف المصدر، مع معالجة تحديث الطلب بصورة ذرية.
4. ميّز فشل القراءة عن استجابة ناجحة فارغة، واعرض وقت آخر قراءة ناجحة.
5. اختبر تكرار الحوالة، والخصم، واختلاف العملة، والملاحظة الفارغة، والتأخير، والتوقف بعد حفظ الطلب.

هذه إرشادات لتكامل مشروعك؛ المثال لا ينفذ منطق تأكيد الطلبات أو حفظها في قاعدة بيانات.

## الأسئلة والمشكلات

يمكن فتح Issue لوصف مشكلة في **هذه الأمثلة** مع بيانات وهمية فقط. لا تنشر مفاتيح أو جلسات أو أرقام محافظ أو بيانات عملاء. لمشكلات حساب وصل استخدم الدعم داخل المنصة.

فُحص المثال محليًا بالبيانات الوهمية. لم يُختبر بمفتاح عميل حقيقي، ولا يمثل شهادة اعتماد أو ضمان أداء.
